WEEK 6 - WEEKLY TASK: Infrastructure as Code & Configuration Management
========================================================================

1.  Install Terraform and Ansible (Ubuntu / WSL)
    # Terraform (HashiCorp apt repository)
    wget -O- https://apt.releases.hashicorp.com/gpg | sudo gpg --dearmor -o /usr/share/keyrings/hashicorp.gpg
    echo "deb [signed-by=/usr/share/keyrings/hashicorp.gpg] https://apt.releases.hashicorp.com $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/hashicorp.list
    sudo apt update && sudo apt install -y terraform
    terraform -version
    # Ansible
    sudo apt install -y ansible
    ansible --version

2.  Configure a Terraform provider
    Task/terraform/main.tf  ->  provider "local" {} (hashicorp/local)

3.  Create a basic Terraform configuration
    local_file.welcome plus a module that creates one .conf file per application

4.  Use variables and outputs
    variables.tf, terraform.tfvars, outputs.tf

5.  Practice the Terraform workflow
    cd Task/terraform
    terraform init        # download providers, set up the backend
    terraform fmt         # format the code
    terraform validate    # check the syntax
    terraform plan        # preview: shows what will be created
    terraform apply       # create the resources (type yes)
    terraform output      # show outputs
    terraform destroy     # remove everything (type yes)

6.  Understand Terraform state
    terraform state list
    terraform state show local_file.welcome
    The state file (terraform.tfstate) maps your code to real resources.
    It can contain secrets: never commit it (see .gitignore).

7.  Create a basic Ansible inventory
    Task/ansible/inventory.ini

8.  Create an Ansible Playbook
    Task/ansible/playbook.yml

9.  Use Ansible to install a package, create a user, start a service
    cd Task/ansible
    ansible all -m ping
    ansible-playbook playbook.yml --check      # dry run
    ansible-playbook playbook.yml
    Verify:  which htop   |   id devopsuser   |   systemctl status cron
    (WSL without systemd: change service_name or enable systemd in /etc/wsl.conf)

    See Task/Report.pdf and the table in README.md
